# Документация проекта "Debug Protocol"

## 1. О проекте

**Debug Protocol** — это веб-игра, обучающая отладке кода в формате RPG-битвы.

**Сюжет:** Компьютер персонажа поражает вирус, который деформирует написанный им ранее код. Игроку предстоит находить и исправлять ошибки, чтобы победить боссов (вирусы). Каждое правильное исправление наносит урон врагу. Цель — пройти все уровни, очистив систему от вирусов.

**Стек технологий:**
- **Frontend:** Vue 3 (Composition API), Vite, Pinia (для стейт-менеджмента), Vue Router.
- **Стили:** CSS (БЭМ-методология), адаптивная верстка.
- **Данные:** JSON (локальное хранение уровней и конфигов).

## 3. Правила работы с Git

### 3.1. Ветки
- `main` — продакшн-версия (стабильная, только для релизов).
- `dev` — основная ветка для разработки (сюда мержим все готовые фичи).
- `feature/andrey-design` — ветка Андрея (дизайн и стили).
- `feature/artem-layout` — ветка Артёма (верстка).
- `feature/leha-layout` — ветка Лёхи (контент и тестирование).

### 3.2. Ежедневный алгоритм работы

> **Важно!** Перед началом работы всегда подтягивай последние изменения из `main`, чтобы избежать конфликтов.

```bash
git checkout main
git pull origin main
git checkout feature/твоя-ветка
git merge main

## 3.3. Как создать Pull Request (пошаговая инструкция)

### Шаг 1. Подтяни свежие изменения из `main`
```bash
git checkout main
git pull origin main
git checkout feature/твоя-ветка
git merge main

Шаг 2. Запушь свою ветку на GitHub
```bash
git push origin feature/твоя-ветка

Шаг 3. Открой Pull Request на GitHub
Перейди в репозиторий → вкладка Pull requests → кнопка New pull request.

Укажи:

base → dev

compare → feature/твоя-ветка

Заполни заголовок и описание PR.

Добавь в ревьюеры тимлида.

Нажми Create pull request.

Шаг 4. Дождись ревью
После проверки тимлид выполнит слияние (merge) в dev.

⚠️ Запрещено: пушить напрямую в main или dev, а также самостоятельно мержить PR без ревью.
